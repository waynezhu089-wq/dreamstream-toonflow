# DS-V03-CORE-001C-B — AI Supervisor acceptance

Implementation status: `READY_FOR_HUMAN_ACCEPTANCE`. This extends the accepted 001C-A review framework; it does not attach the Supervisor Gate to any accepted Production Profile, advance a Stage, or modify a Storyboard.

The Review Definition fixes the `SUPERVISOR` Skill type and `supervisor-review` Stage. The server reads the current project/script, exact Profile and Recipe, and the semantic Storyboard snapshot in one SQLite transaction. Stage Skill resolution uses `SYSTEM < PROFILE < exact RECIPE < PROJECT < STAGE`, with no SHOT layer. Exact Skill and ordered overrides form `supervisorResolutionHash`. `/api/supervisor/ai/context` is read-only and shows this resolved policy. It never calls a model.

`/api/supervisor/review/ai` accepts only projectId, scriptId, reviewKey, expectedTargetHash, and expectedControlContextHash. It rejects stale or oversized input before model selection, closes the read transaction before calling a text model, pins the actual provider/model for at most two structured-output attempts, then rechecks target, control context, and policy in a new write transaction. Only an unchanged result appends an immutable AI review. Runtime/provider errors are not retried; malformed structured output gets at most one repair. No free-text JSON parsing is used.

The Gate uses the latest current HUMAN PASS/REVISE first, then the latest current AI result whose policy hash matches. AI HUMAN_CONFIRM blocks and asks for a human decision. Changing the Skill or an override stales AI reviews but leaves current HUMAN reviews effective. Model configuration changes alone do not stale an AI review. History exposes CURRENT/STALE, `staleReason`, and a separate `effective` marker.

Human acceptance uses a disposable project and a deliberately configured **text** model. Do not run paid-model calls in automated tests. Bind an activated SUPERVISOR Skill to the trusted Stage or another supported scope, open `Advanced · Supervisor Review`, and inspect the exact Skill/version/overrides before using “AI 审查当前版本.” Verify PASS, REVISE with BLOCKER, and HUMAN_CONFIRM against the same Gate; then verify that a later current HUMAN decision wins. Change a Storyboard semantic field and then a Skill override to confirm separate target and policy staleness. Confirm no Stage or Storyboard state is changed by AI review. The canonical freeze's marker-based test protocol remains the acceptance authority.

Automated coverage: `tests/supervisor-ai.test.cjs` uses the real Toonflow database wrapper, temporary SQLite, HTTP routes, and stubbed structured model sessions. It covers additive migration, resolver priority/exact Recipe, no off-transaction reads, freshness, payload bound, structured decisions and one repair, provenance, Gate priority, and no hidden production mutation. Frontend tests exercise the current-unit AI context, request hashes, duplicate-call lockout, and AI error isolation.
